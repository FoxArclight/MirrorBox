# 镜岛推箱 / Mirror Isles Workshop

这是一个基于 Godot 4.6 的俯视 2D 推箱游戏。核心玩法是“推动 + 镜面反射”：角色和箱子可以沿镜子进行投影、复制和传送；箱子完成目标后出口开启，玩家到达出口才算通关。

## 运行工程

1. 使用 Godot 4.6 打开本目录。
2. 打开 `project.godot`，主场景为 `res://scenes/main.tscn`。
3. 点击运行项目即可进入主菜单。

## 游戏操作

| 按键 | 作用 |
| --- | --- |
| 方向键 / WASD | 同步控制所有当前存活的角色移动 |
| Space | 执行镜面反射 |
| Z | 回退最近一个推动或反射检查点 |
| R | 重开当前关卡 |
| Esc | 返回选关 |

箱子全部到达箱子终点后，出口从红色关闭状态变为绿色开启状态；只有玩家进入已开启出口才会通关。

## 回退系统

回退不是简单地“撤销上一帧移动”，而是面向解谜操作设计的检查点系统：

- 开局没有回退记录。
- 普通走路不会添加回退记录。
- 成功推动任意可推动物体时，系统会记录推动前的完整状态，包括玩家、箱子、镜子、桥面和操作计数。
- 如果连续推动的是同一个物体、方向也相同，并且只是普通连续推动，中间状态会合并，不会让 Z 逐格回退。
- 换了推动物体或方向，或者这次推动产生了落水铺桥、触碰机关等特殊效果，就会建立新的检查点。
- 每次成功的 Space 反射都会单独记录检查点；一次反射生成多个对象时也只对应这次反射操作。
- 按 Z 会恢复最近检查点；连续按 Z 可以继续回到更早的推动/反射前状态。撤回也会同步恢复实体状态、桥面、胜利状态、计数和回退时间线。
- 失败的移动、推动或反射不会改变状态，也不会污染回退列表。

## 镜面反射

镜子有两种 45° 方向。只有角色或箱子与镜子同行或同列时，才会显示反射目标预览和连接光束。

- 墙、箱子和角色都会遮挡对应方向的光线；海水不会遮挡镜面视野。
- 一次 Space 会处理所有满足条件且没有被遮挡的角色和箱子。
- 同一个对象同时被两面镜子反射，会生成两个结果；如果多个结果落在同一格，会合并为一个对象，避免重叠角色在下一步移动时产生异常。
- 蓝色预览表示可到达，黄色表示水面危险但仍允许反射，红色表示墙体、占用等无效目标并阻止该条反射。
- 角色反射到水面会死亡并产生水花；只要仍有可操控角色，游戏继续，全部角色落水才失败。
- 箱子反射到水面会保留水下箱体表现并生成可行走的桥面，和正常把箱子推入水面一致。
- 场景外没有硬边界，边界外统一按水面处理。

## 关卡编辑器

从主菜单进入“关卡编辑器”。编辑器默认创建 `16×16` 棋盘，棋盘宽高可分别调整为 `6–32` 格。

### 工具与鼠标

- 左侧是地形：陆地 `1`、水面 `2`、墙 `3`。地形可以直接覆盖。
- 右侧是物体：角色、箱子、镜子、箱子终点、出口和字体。物体可以从工具栏按住左键拖入棋盘。
- 在棋盘上左键点击并拖动物体时，是移动物体，不会铺设地形；物体不会覆盖其他物体。
- 右键删除当前格中的对象、目标点、出口、镜子或字体；地形不能被删除，只能覆盖。
- 鼠标中键吸取当前位置的工具；鼠标滚轮缩放棋盘。
- 缩放使用绝对像素格大小：最小值完整显示当前棋盘，最大值约为画面纵向显示 8 行。
- 棋盘放大后可用 `WASD` 移动镜头。
- 镜子只有一个工具，点击已放置的镜子可以旋转 90°。

### 字体工具

字体是独立的关卡注释，不参与碰撞和通关。可以放在棋盘内或棋盘外，并设置：

- 文字内容
- 字号
- 文字颜色
- 背景 Alpha

场上字体左上角的十字手柄用于自由拖动，右上角的 `T` 手柄用于编辑；选中字体工具后，双击文字也可以编辑。字体位置不按整数格限制，背景会随文字内容和字号自动适配。

### 文件与编辑操作

- 顶部提供“打开”“保存”“另存为”。打开使用文件浏览器选择 `.json` 关卡；另存为可以填写地址和文件名。
- `Ctrl+Z` 撤销，`Ctrl+Y` 重做；一次连续铺画、一次物体拖动、一次文字编辑或一次棋盘尺寸调整均作为一个编辑操作。
- 编辑器会检查缺少角色、出口、箱子或目标点等结构问题。红色错误阻止试玩，黄色提醒允许试玩。
- 关卡数据格式为 JSON，内置关卡位于 `data/levels/`，顺序由 `data/campaign.json` 决定。

## 工程结构

- `data/`：正式关卡和战役顺序。
- `scenes/`：主场景及测试场景。
- `scripts/core/`：关卡数据、棋盘状态、规则、历史和校验。
- `scripts/main.gd`：主菜单、正式游玩、编辑器和编辑试玩流程。
- `scripts/ui/`：关卡编辑器界面与工具图标。
- `tests/`：规则回归测试。
- `docs/`：规格、架构、编辑器流程和验收记录。

用户创建的关卡和本地档案默认保存到 `user://levels/` 与 `user://profile.json`，不会修改 `res://` 下的正式资源。
